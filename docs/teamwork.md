# Working together on a Data Science project

## Context

The MSFT predictor was Group 15's Year 1 Block D project for Data Science Lifecycle Management. Kanban and group management were central to the assignment. The goal was to coordinate a complete project, not simply maximise a model score.

## Kanban and shared ownership

We used Kanban to organise the team's work and make responsibilities and progress visible. Different workstreams included the project proposal, data preparation, modelling, application design, testing and the dashboard. Keeping those tasks connected mattered because a change in one component could affect another member's work.

This public case study describes the approach. It does not recreate a historical board or claim measured improvements in delivery time or throughput.

## Coordinating changes

The project evolved from predicting a numerical price to predicting direction. The final application then used weekly, three-class predictions. That meant the problem statement, evaluation criteria and application descriptions needed to evolve together.

A documented team discussion identified inconsistencies between independently written sections of the proposal. Reviewing the complete document together helped reveal those differences. The lesson was to keep shared assumptions explicit rather than assume each workstream was using the same definition of the task.

## Git and integration

The team discussed merge conflicts caused by branches diverging from main. We agreed to pull changes more frequently, keep branches closer to main and use smaller commits. That agreement is documented in the original school materials; it is not presented here as a quantitative claim about later delivery performance.

## My work within the team

The final application combines work from multiple team members, including the weekly XGBoost model attributed to Timur in the source.

## What I take from the project

An individual experiment is only one part of a shared application. Work needs clear ownership, assumptions need to be communicated, documentation needs review, and separate contributions need regular integration. These are the aspects this portfolio project is intended to demonstrate.

## Evidence and scope

This summary draws on the original Kanban assignment, team meeting record, shared design report, experiment folders and final application.
